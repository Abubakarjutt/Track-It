## Recommended order

### 1. `2026-09-11-cluster-5-device-verification.md` — **do first**

Cluster 5 is the only thing between the current tree and a shippable build. Most
of it needs a physical iPhone, but the spec separates the **in-repo prep** (small,
doable now) from the **device pass** (yours). Doing the prep first means the
device pass is a clean checklist run, not a debugging session.

### 2. `2026-09-11-cluster-6-accuracy-gate.md`

The hard-CI-gate promotion is blocked on 5a's recogniser running on a device to
generate real hypotheses. But the **in-repo prep** — widening the 14-row corpus,
restructuring the harness to load audio-derived fixtures — is independent and
worth doing before the recordings exist.

## How to turn one of these into working code

1. Read `2026-09-11-v1.1-remaining-onboarding.md`.
2. Read the cluster spec end to end.
3. Resolve every line under **OPEN QUESTIONS** with the repo owner. Write the
   answers into the spec (a `> **Resolved <date>:** …` block under each question)
   and commit that as `docs(specN): resolve open questions`.
4. If the spec's "Effort" says a `writing-plans` pass is warranted, produce
   `docs/superpowers/plans/<date>-v1.1-cluster-N-<slug>.md` first (see the
   existing `2026-09-06-v1.1-cluster-5-telemetry-latency.md` for the house
   format).
5. Implement with the TDD → review → finish rhythm from the onboarding doc.
